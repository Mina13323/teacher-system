# سيناريوهات الاختبار اليدوي الشاملة — منصة المصري التعليمية

**نوع الوثيقة:** دليل اختبار قبول المستخدم (UAT) — تنفيذ يدوي في المتصفح
**نطاق التغطية:** الأدوار الأربعة كاملة (مدير النظام · المعلم · المساعد · الطالب)
**المرجع البرمجي:** الفرع `arena/01a067b3-teacher-system`
**عدد السيناريوهات:** 199 سيناريو مرقّم + 8 قياسات تجاوب

---

## كيفية استخدام هذه الوثيقة

كل سيناريو مرقّم برمز ثابت (مثل `STU-07`) حتى يسهل الرجوع إليه في تقارير الأخطاء.

| العمود | المعنى |
|---|---|
| **الهدف** | ما الذي يثبته هذا السيناريو |
| **المتطلبات المسبقة** | ما يجب تجهيزه قبل البدء |
| **الخطوات** | التنفيذ بالترتيب |
| **النتيجة المتوقعة** | معيار النجاح — أي اختلاف عنها يُعد خللاً |
| **الحالة** | ✅ نجح · ❌ فشل · ⏭️ تخطّي · ⬜ لم يُنفَّذ |

**قاعدة عامة:** أي سيناريو يفشل يجب توثيقه برقمه + لقطة شاشة + الرسالة الحرفية الظاهرة.

## 1. بيئة الاختبار والبيانات الأولية

### 1.1 الحسابات الجاهزة

| الدور | البريد الإلكتروني | كلمة المرور | المصدر |
|---|---|---|---|
| مدير النظام | `admin@example.com` | `password` | `DeveloperUserSeeder` |
| المعلم (حساب البذر) | `maherelmasry@teacher.com` | من المتغير `TEACHER_ACCOUNT_PASSWORD` (أو `change-me-locally` محليًا/في الاختبارات فقط) | `TeacherAccountSeeder` |
| مساعد | يُنشأ أثناء السيناريو `TCH-14` | — | — |
| طالب | `ELM-1001` أو `elm-1001@student.com` | `ELM@#####` (خمس أرقام عشوائية) | يُنشأ أثناء `TCH-12` |

> ⚠️ **تنبيه أمني:** كلمة مرور حساب المعلم موجودة كنص صريح داخل مستودع الكود. يجب تدويرها قبل أي بيئة إنتاج، واستبدالها بمتغير بيئة `TEACHER_ACCOUNT_PASSWORD`.

### 1.2 قواعد تسجيل الدخول

- حقل «اسم المستخدم» يقبل **البريد الإلكتروني أو كود الطالب** معًا.
- كود الطالب غير حساس لحالة الأحرف (`elm-1001` = `ELM-1001`).
- الحساب المعطّل (`is_active = false`) يُرفض برسالة مختلفة عن رسالة البيانات الخاطئة (انظر ملاحظة الرسائل بالأسفل).
- كلمة مرور الطالب المؤقتة صيغتها `ELM@` متبوعة بخمسة أرقام **عشوائية** — لا يمكن اشتقاقها من كود الطالب أو السنة الدراسية.

### 1.3 القيم المرجعية للأنظمة

| النظام | القيم المسموحة |
|---|---|
| حالة وصول الطالب | `active` · `due` · `pending_review` · `expired` · `suspended` |
| باقة الصلاحيات | `ALL` · `LESSONS_ONLY` · `EXAMS_ONLY` · `COMPETITIONS_ONLY` · `NONE` · `CUSTOM` |
| الصف الدراسي | `secondary_1` · `secondary_2` · `secondary_3` |
| حالة الكورس / الامتحان | `draft` · `published` · `archived` |
| حالة المسابقة | `draft` · `published` · `active` · `ended` · `archived` |
| حالة المحاولة | `in_progress` · `submitted` · `grading` · `published` · `expired` |

## 4. ملاحظات تنفيذية

1. **الترتيب مهم:** القسم B يُجهّز البيانات التي يعتمد عليها القسمان C وD. لا تنفّذ D قبل B.
2. **بيانات الدخول لمرة واحدة:** سجّل كلمة مرور الطالب فور كشفها في `TCH-12` — لا يمكن استرجاعها لاحقًا، وهذا سلوك مقصود.
3. **الاختبارات الزمنية:** سيناريوهات `STU-40..46` تتطلب ضبط ساعة الجهاز أو استخدام نوافذ زمنية قصيرة (دقائق).
4. **فحص الشبكة:** سيناريوهات `SEC-*` و`STU-19` و`STU-30` و`STU-49` تحتاج فتح أدوات المطور ← تبويب Network.
5. **قبل بيئة الإنتاج:** يجب تدوير كلمة مرور حساب المعلم الموجودة في المستودع، وضبط `TEACHER_ACCOUNT_PASSWORD` عبر متغيرات البيئة.
6. **ملاحظة على رسائل الـ API:** رسائل الأخطاء الصادرة من الخادم **إنجليزية** حتى الآن (`This account has been disabled.` · `The provided credentials are incorrect.` · `You are already enrolled in this course.`)، بينما واجهة المستخدم عربية بالكامل. عند تنفيذ السيناريوهات أعلاه تحقّق من **الدلالة** لا من نص الرسالة. ظهور نص إنجليزي للمستخدم النهائي يُعد ملاحظة واجهة تستحق التسجيل، وليس فشلًا في السيناريو.
